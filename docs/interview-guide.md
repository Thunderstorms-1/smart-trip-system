# 面试演示与答辩准备

## 五分钟演示

1. 游客打开首页和旅行广场，查看作者主页与路书快照，说明个人邮箱/账号字段只存在于私密资料。
2. 登录 demo_traveler，修改昵称、简介和偏好，上传PNG/JPEG头像。展示页面刷新后仍保留数据。
3. 手动创建三日路书，编辑地点/日期/费用，跨天移动节点，再保存。指出一个保存请求同时更新日期、排序和预算。
4. 打开两个浏览器页分别编辑同一份路书；后保存的一页收到409冲突。再从历史恢复，展示恢复也保留旧版本。
5. 从节点打开费用表单，核对实际金额；对照“预估预算”和“实际消费”。添加并勾选基础行李清单。
6. 显式发布快照，修改私密路书后检查公开内容仍是旧快照；更新公开快照才变化。创建分享，社区下架后分享仍可访问，再撤销分享验证失效。
7. 用 demo_companion 点赞/取消、收藏、评论/删除自己的评论、克隆。强调克隆后的Trip ID、所有者和私密状态独立。

AI、地图、天气未确认免费权限，演示时直接说明默认关闭，展示适配器和测试证据。不要把测试固定响应或手动示例说成现场模型调用、真实交通或实际天气。实际免费凭证接通后，再补在线验收。

## 可以用证据回答的问题

| 问题 | 回答要点与代码 |
| --- | --- |
| 为什么重构？ | 原来页面分别维护状态，重复请求、假天气/坐标、权限不一致。现在围绕同一Trip领域联动，公开内容独立快照。 |
| 怎么避免越权？ | ResourceAccess逐资源验证，不只看客户端userId；Tool和排序检查真实节点归属。测试使用两个账号证明403。 |
| 并发编辑怎么办？ | 数据库行锁+version校验+409；不是最后一个请求静默覆盖。旧AI提案也接受同一检查。 |
| AI失败会留半份行程吗？ | 上游调用在事务之外，完整结构验证后交给独立事务服务落库；任务成功与行程持久化同事务。 |
| 为什么Redis锁还要数据库状态？ | 锁限制同用户并发运行，持久状态、请求唯一约束和事务保证重试/完成不重复保存；TTL长于上游callTimeout。 |
| 同类任务重试怎么控制？ | 请求标识唯一，已存在任务返回原ID；同标识不同输入拒绝。断线进度不取消任务，可查询持久状态。 |
| 预览和保存怎么区别？ | MODIFY先存PREVIEW与baseVersion，用户确认后才事务应用，并保留历史版本。 |
| 点赞计数如何正确？ | 关系表唯一键，操作是设置目标状态；计数从真实关系表汇总。重复“点赞”不能产生第二条记录。 |
| 为什么不直接把预估导入账单？ | 预估与实际消费含义不同；节点只预填，用户确认才记账。请求幂等防重复收费记录。 |
| 分享链接怎么控制？ | 高熵随机token，只存摘要；快照独立于私密草稿和社区状态，可单独撤销。 |
| 模型输出可靠吗？ | 视作不可信输入，校验结构、数量、时间、费用和稳定ID；不接受模型编造的地图、评分或天气。 |
| 地图是真的了吗？ | 适配器请求实际供应商路线，不补点/画直线；当前凭证未启用，只完成代码和固定响应契约测试。 |
| 项目怎么复现？ | 配置样例、Flyway独立库、启动脚本、种子账号、单元/集成/浏览器测试。中文路径构建有专门脚本。 |

## 诚实描述项目规模

适合描述为“旅行路书产品的全栈渐进重构”，不要说微服务、高并发系统、商业推荐引擎或实时多人编辑。当前是单实例应用、关系数据库事务、两个AI执行线程和本地演示环境。

简历可写：统一路书与公开快照领域，完成用户资料/资源授权、版本冲突与历史恢复、互动幂等与可撤销分享，补充外部AI/地理服务边界及多层验证。具体性能数字只引用本项目构建产物和实际测试，不编造QPS、用户量或线上事故收益。

继续提升的方向：Repository进一步统一、结构化AI操作提案优化、供应商实际免费接通验收、更多真实旅途可用性测试。后续才考虑分布式调度、推荐、足迹和实时协同。
