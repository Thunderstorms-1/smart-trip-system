## 实际视觉落地

首页沿用批准稿的整幅湖岸概念影像、跨画面的旅程序列、少量浮动玻璃导航/状态/行动区，以及下方冷白阅读区。摄影承担旅行氛围，橙色承担路线与行动提示；正文使用清晰无衬线字体，时间和数值使用等宽数字。首页局部使用冷色文字（`#1f303d`）、浅背景（`#f4f7f9`）和路线橙（`#ef7942`）；这些是当前 Home 实现事实，不升级为全站新令牌。

桌面为照片主场景、继续旅行条、序列示意与时间线并列、公开旅行灵感和下方照片/路书摘要。700px 以下使用独立移动端路线构图，重组导航和规划入口，序列与时间线改为便于阅读的布局。按钮、链接有键盘焦点反馈；提供跳到主要内容入口；减少动态偏好关闭路线揭示等动画。

`.v3-shell` 只在路径为 `/` 时启用，所有新样式均限于该边界。离开首页后恢复现有 Shell 与页面样式，避免首页视觉泄漏到其他业务页。

## 数据、交互与诚实边界

- 公开灵感读取现有 `GET /community/posts`，显示返回结果的前 3 条；游客首页读取首条公开帖详情，使用其路书快照。
- 登录用户先读取 `GET /workbench` 摘要列表，再读取首条返回记录的 `GET /workbench/:id` 详情。继续旅行和相关节点进入真实 `/trip/edit/:id`；个人列表为空时回退公开快照，但不将公开旅行显示成个人路书。
- Hero 最多显示 4 天，节点名来自当日首个安排或主题；时间线与小图使用首个有活动的日期，最多展示其前 3 个安排。完整路书入口保留；图中长名称缩略，关联时间线保留完整名称。
- 原静态天气、距离、交通耗时和完成进度等演示数值不进入正式首页。状态区显示真实保存天数与安排数量；时间线使用保存的开始时间、停留时长与预估费用，缺项明确显示待定。日活动时长仅在该日全部时长有效时汇总，不等同于含交通的全天时长。
- 规划入口使用已有 Generate 路由，不提供其尚未支持的首页输入；手动创建进入现有 `/ai-generate?mode=manual`。受保护入口继续使用原登录跳转。
- Hero 连线与小图明确标注“顺序示意，非导航路线”，小图不代表真实地理坐标；概念影像明确标注“非目的地实拍”。没有天气、路线、地图 SDK 或 AI provider 新调用。
- 公开列表与个人行程分别提供加载、空态、失败及重试反馈。照片失败时保留布局与可用入口，并显示影像不可用；不会用静态样例填补业务空数据。
- 登出或会话变化立即清空私人行程，取消过期请求，并再次核对响应所属 token；迟到的私人响应不能重新出现在游客首页。原会话过期清 token 与登录 redirect 行为保留。
