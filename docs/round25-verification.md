# SmartTrip 2.5 轮收尾验收

日期：2026-10-04。基线 cde017c，分支 fix/smarttrip-round25。本轮仅做已确认的三个收尾点，下一轮的新功能尚未选定或实现。

## 最终实现

1. **地点解析与路线期限**：仍先解析 POI 引用，无引用才用有效已有 GCJ02 坐标。搜索坐标非法则跳过，详情非法则未解析；数字长度/精度有界，避免异常数字展开。每次路线查询内同一 POI（含未找到）只解析一次，每个节点仍保留自己的 ID/名称。
2. **查询与 SDK 生命周期**：路线/天气独立加载、错误与取消；切换 Trip/版本/日期/方式、未保存状态及卸载使旧结果与错误失效。普通查询复用当前页面的路线，重新查询明确发请求，页面显示查询时间；不写持久存储。SDK 共享 Promise，失败移除自己创建的脚本后可重试，迟到加载不绘制旧页面。
3. **会话身份校验**：401 仅清除请求所用且当前仍保存的同一个令牌；旧令牌的迟到 401 不清除新会话，当前会话过期仍正常退出，认证接口保持独立失败提示。

## 超时与接口

| 位置 | 行为 |
| --- | --- |
| 路线后端 | 30 秒总期限；单次上游最多 15 秒且受剩余时间约束；期限耗尽 HTTP 504，停止后续调用，不返回半份成功路线 |
| 其他上游连接故障 | 继续使用已有 502；关闭自动连接重试和自动重定向，避免隐藏的额外调用 |
| 路线/天气前端 | 35 秒等待上限，超时取消请求并允许重试 |
| 地图 SDK | 配置请求与脚本加载共用 10 秒期限，失败/超时清理后可重试 |

接口路径与 JSON 响应结构保持；TypeScript RouteData 补齐后端原本返回的 retrievedAt 字段。没有数据库迁移，数据仍为 POI 引用，不增加供应商缓存。
