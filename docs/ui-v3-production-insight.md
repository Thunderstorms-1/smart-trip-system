## 范围与设计依据

本轮完成右侧真实 Quality Insight，属于已批准 V3 工作台的普通延伸。根 `DESIGN.md` 与已批准静态 V3 工作台仍是设计依据；不改根设计、PRODUCT、sidecar 或静态原型。延续非地理规划画布、浮动工作面与紧凑时间轴，密集洞察采用稳定可读内容面。

仅涉及前端 `Editor.vue`、`ItineraryAnalysis.vue`（新增报告事件桥接）、`workbench/{QualityInsight.vue,useWorkbenchQuality.ts,WorkbenchShell.vue,workbench-quality.test.ts}`、`workbench-v3.css`、新增 `e2e/insight-v3.spec.ts`，以及既有 `e2e/analysis.spec.ts` 的断言范围调整。完整 Inspector、provider、地图天气、AI 与后端不在本轮修改范围；Home V3 保持原样，2C / 2D / 2E 尚未由本轮完成。

## 真实数据与报告有效性

- 洞察显式调用已有 `POST /workbench/{id}/analyses`，提交已保存 `baseVersion`、全部真实 day ID 与 `mode: walking`，使用现有后端 Quality 引擎的 `TRIP` 报告。既有行程诊断只通过新增 `report` 事件把当前报告交给洞察，不重写其流程。
- 四个维度直接来自报告：`TIME` 时间安排、`PACE` 行程节奏、`MEAL_REST` 用餐与休息、`BALANCE` 每日均衡。`READY` 的真实 0 分显示为 0；`UNKNOWN` 显示暂无法判断，`NOT_APPLICABLE` 显示不适用，两者均不绘制评分条；`totalScore: null` 不生成总分。
- 同时展示质量 findings、依据及基础冲突，按问题 ID 去重。定位按当前完整树查找节点的实际所属日期，不把跨日问题的首个节点默认归到首个 day ID；仅日期问题定位日期安排。
- 报告绑定完整行程树、trip ID、报告 `baseVersion`、quality `baseVersion`、无未保存草稿及有效到期时间。任意草稿树编辑立即清除报告并取消请求；迟到响应不能恢复评分。撤销编辑、保存或版本变化均不会复活旧报告，须重新分析。切换显示日期不改变全行程报告。
- 未分析、分析中、未保存变化、过期 / 版本不匹配及失败重试具有明确状态；失效时不显示旧总分或维度条。请求有超时和取消处理。

阶段名称沿用 Quality V2，但既有后端 `rulesVersion: quality-v1` 没有改名。路线与天气不参与核心评分，未取得的外部信息不被当作已知值。

## 响应式与操作行为

桌面保留右侧洞察。平板及手机通过显式“行程洞察”入口打开，入口声明展开状态；打开后焦点进入关闭按钮，Escape / 关闭回到入口，切换工具导航关闭洞察。手机打开洞察时隐藏时间轴，保持一个主面板；问题定位关闭洞察、展开时间轴并聚焦真实节点。新增样式全部限定工作台，不影响 Home V3。

## 复现步骤

1. 启动项目现有前后端，登录并打开一份已保存路书；手机 / 平板先点击“行程洞察”。未分析时应无评分。
2. 点击“分析已保存行程”，核对请求含当前保存版本和全部 day ID；面板显示实际报告的四维状态、问题与可用总分。
3. 点击跨日问题的节点定位，应进入节点实际所在日期并聚焦节点；通过已有“行程诊断”检查后返回编辑，也可接收当前有效报告。
4. 编辑任意草稿字段，确认旧评分立即消失；撤销或保存后仍须重分析。在分析响应返回前编辑，迟到结果也不得恢复评分。
5. 用单日缺时间路书验证 UNKNOWN、NOT_APPLICABLE 与空总分；在窄屏验证开关、Escape 焦点回返、定位关闭及页面无横向溢出。
